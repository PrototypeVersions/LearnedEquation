00 / THE IDEA

First, shrink the world.

Imagine a language with just six tokens: the, cat, dog, runs, sleeps, . A token is one item in our vocabulary. Each word is one token, and the period is a token too.

Give the model a sequence such as the cat. Its job is to assign a probability to each possible next token. A probability is a share between 0 and 1: 0 means impossible, 1 means certain. Multiply by 100 to express it as a percentage. It doesn’t return a whole sentence in one go.

These are hand-picked weights, not the result of training. This is an attention-only teaching model, not a full transformer. Its weights favor a tiny sentence pattern: “the” → a noun → a verb → a period. This is a soft preference, not a grammar filter; every next token still has a nonzero probability.

01 / REPRESENT

Words in.
Numbers inside.

A computer needs numbers to calculate with. An embedding is a lookup table that gives each token a list of numbers.

A list is called a vector. Square brackets, such as [1, 0], hold its entries in order. Ours has two entries, so we can draw each token as a point on a plane. Here we deliberately assign coordinates by role: “the” points right; nouns point up; verbs point left; the period points down. “cat” and “dog” share a vector, as do “runs” and “sleeps.” This model cannot distinguish tokens with identical embeddings. Real embeddings are usually learned.

Tap a token to find its point.

A TWO-NUMBER ADDRESS
Two coordinates. Six tokens. Four shared roles.

A matrix is just a table.

Stack the vectors as rows and you have a matrix. We call the embedding table E. The name is shorthand for these twelve fixed numbers.

Look up the input.

Let x be the input sequence and n its length. Write X = E(x) for “look up each input token and stack its vector.” The equals sign means both sides have the same value; E(x) means “apply the lookup E to input x.” X is a table with n rows and 2 columns.

the cat→

Capital letters name tables; lowercase letters usually name a vector or a number. Subscripts identify entries: X₂,₁ = 0 means row 2, column 1. We count from 1.

02 / TRANSFORM

A matrix is also
a recipe.

Multiplication combines an input row with each recipe column. Match pairs, multiply each pair, then add. That’s a dot product.

The inner sizes must match: (1 × 2) times (2 × 2) gives (1 × 2). For a whole matrix, repeat this row-by-column recipe for every output entry.

Read the symbols as verbs.

AB means “multiply matrix A by matrix B,” in that order. It usually differs from BA. Aᵀ means transpose: turn A’s rows into columns. A dot, q · k, means the dot product of two vectors.

What are weights?

The fixed numbers in these recipes are called weights. Training normally adjusts them using data. For this lesson, every weight is given explicitly. The calculations change with your prompt; the weights don’t.

03 / ATTEND

Which words
should mix?

Attention lets each position mix information from the tokens available to it. A larger match earns a larger share of the mixture.

Q

Query

“What am I looking for?”

Multiply X by WQ to make a query for every row.

Key

“What can I match?”

Multiply X by WK to make a key for every row.

V

Value

“What do I contribute?”

Multiply X by WV to make a value for every row.

These questions are an analogy for numerical roles, not literal questions the model asks.

For “the cat,” the final query is [0, 2]. The keys are [2, 0] and [0, 2]. Their dot products are 0 and 4.

[0, 2] · [2, 0] = 0
[0, 2] · [0, 2] = 4
B

Scale

Divide by √2, the square root of our key size. The symbol √ means square root: √2 is the positive number whose square is 2. The symbol ≈ below means “approximately equal.” This is the standard attention scaling rule: divide by √d for keys with d entries.

scores ≈ [0, 2.8284]
C

Respect the past

A position can see itself and earlier positions. Future positions are blocked. This is a causal mask. The final input position can see the whole prompt.

the → the
cat → the + cat
The table version: Q = XWQ, K = XWK, V = XWV. Then QKᵀ compares every query with every key. Its row i, column j is the match from position i to position j.
04 / NORMALIZE

Turn scores
into shares.

Raw scores can be negative and don’t sum to one. Softmax turns a list into positive proportions that add up to 1. Higher scores get larger shares.

The first score stays at 0.

Exponentiate. Then divide.

e is a fixed number, about 2.71828. Raising it to a score gives a positive value. Divide by the sum of all these positive values. Call the score list s. The index j selects the entry we want; k runs over all entries. The symbol ∑ means “add them all.”

softmax(s)j = esⱼ / ∑k esₖ

In the playground, we subtract the largest score before exponentiating for numerical stability; this gives the same mathematical result.

Use those shares to mix values.

For our original scores, softmax gives about [0.0558, 0.9442]. That means 5.58% of the “the” value [1, 0] plus 94.42% of the “cat” value [0, 1].

h = 0.0558[1, 0] + 0.9442[0, 1]
h ≈ [0.0558, 0.9442]

Two uses, one operation.

Here softmax allocates attention across input positions. Later, it allocates probability across vocabulary tokens. These are different lists with different meanings.

For a whole attention table, apply softmax separately to each row. We’ll call that R. A blocked score is written −∞ (negative infinity); its exponential is 0, so its share is exactly 0.

05 / PREDICT

One mixed vector.
Six possible futures.

The final-position mixture, h, has just two numbers. An output projection multiplies it by WO, turning it into six scores called logits.

z = hWO ≈ [−3.7768, 0.2232, 0.2232, 3.7768, 3.7768, −0.2232]

In vocabulary order: the, cat, dog, runs, sleeps, period. Apply softmax once more to get the next-token distribution.

A distribution is the model’s answer. “runs” and “sleeps” tie for the largest probability. We break ties in vocabulary order, so “runs” wins. Sampling would draw randomly according to these probabilities. To generate a longer sequence, append the chosen token and calculate again. The model is fixed; a random choice adds randomness outside it. Repeating this from “the cat” produces “the cat runs.” The period is a real predicted token: completion stops when it appears.

Why these numbers make a sentence

Query and key weights amplify each coordinate by 2. Identical roles get a dot product of 4, adjacent roles get 0, and opposite roles get −4. For a normal short prompt, attention therefore mostly preserves the final token’s role.

The projection encodes the next role.

A right-pointing “the” vector gives high logits to nouns; an up-pointing noun gives high logits to verbs; a left-pointing verb gives a high logit to the period. Each behavior comes directly from the columns of WO. There is no separate grammar checker.

An n × n causal mask. Mij = 0 when j ≤ i; otherwise −∞. Adding it blocks future positions.

08 / ZOOM OUT

Same idea.
A much bigger composition.

A real transformer adds many more recipes. Fix the weights, and those recipes still compose into one mathematical function.

A layer is a stage that transforms a table of vectors into a new table. A full transformer layer typically combines attention with a feed-forward network, plus residual additions and normalization.

Many attention heads
Several query/key/value recipes run in parallel and their results are combined.
Position information
Position embeddings or transformations such as rotary position encoding let order affect computation.
Feed-forward networks
Additional learned transformations and nonlinear functions process each position.
Residuals & normalization
Residuals add a stage’s input back to its output. Normalization controls the scale of vector entries.
Many layers & a larger vocabulary
The process repeats. Tokens can be word pieces, punctuation, or other units rather than whole words.
Tokens→Embeddings + position→Layer 1 → … → Layer L→Logits→Probabilities

This toy omits those full-layer components. Its 36 fixed scalar weights (12 embedding + 12 query/key/value + 12 output) describe a simplified attention language model. For an actual implementation, precision and execution details also matter to bit-for-bit reproduction. A deployed assistant may add tools, retrieval, system instructions, and a decoding policy around the network.

09 / THE DEEPER QUESTION

When you know every number,
what have you understood?

Could the giant equation be essentially the best description there is?

An exact description isn’t automatically an explanation.

Our equation tells you how to reproduce every output. A higher-level explanation might tell you why a pattern occurs, predict what changes will do, or reveal a reusable rule.

“Simpler” needs a standard. Fewer symbols? Fewer bits to store? Faster calculation? A rule a human finds meaningful? A shorter program can run much more slowly. Those goals need not agree.

Sometimes a shorter exact rule exists.

This toy is a good example. Its final output depends only on the last token and the counts of the six tokens. You can replace repeated attention calculations with six count-weighted terms.

See the smaller exact description of this toy

Let ct be the count of token t. Let q be the final token’s query, kt and vt the fixed key and value of token t. Each sum below runs over the six vocabulary tokens.

h = ( ∑t ct e(q·kₜ)/√2 vt ) / ( ∑t ct e(q·kₜ)/√2 )
F(x) = softmax(hWO)

Repeated tokens have identical keys and values. Grouping their identical contributions by count gives exactly the same final mixture. The full causal table remains useful for teaching, but it isn’t necessary to compute the final output.

But not every function has a compact rule.

There are more possible finite input-output tables than short descriptions. So, under a fixed encoding and size limit, some functions cannot be described much more briefly than by listing their behavior. That counting argument establishes a possibility, not a verdict about trained language models.

The network itself is already a compact recipe compared with an enormous table of all prompts. A shorter architecture formula also hides the information stored in its weights. Whether substantially simpler rules capture a particular model depends on the domain, the allowed errors, and what counts as simpler.

Interpretability can still make progress.

Even if no small, exact, global rule exists, there may be useful local mechanisms, approximate explanations, or compressed descriptions of particular skills. A good explanation should survive tests and interventions, not just sound plausible.

A note on limits of the philosophical claim

Minimal description length depends on the description language; finding a globally shortest program is uncomputable in general. That doesn’t imply a particular finite transformer cannot be simplified, or that it must be simulated step by step to answer every question about it. Useful explanations can be partial, approximate, or specific to a task. For background, see Gregory Chaitin’s discussion of simplicity and irreducibility.
